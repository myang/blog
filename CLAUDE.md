# Blog — Agent Instructions

This is an Eleventy (11ty) static blog with Tailwind CSS and Alpine.js. It ships to
Netlify. This file tells AI coding agents how to work in the repo and — importantly —
how the **auto-validation and auto-repair harness** is wired up.

---

## Project layout

- `src/posts/` — blog posts as Markdown (`YYYY-MM-DD-slug.md`)
- `src/blog/` — a second Markdown area used by a few long-form posts
- `src/_includes/` — Nunjucks templates and partials
- `src/_data/` — global YAML data (navigation, settings)
- `src/static/img/` — images served under `/static/img/...` on the built site
- `_site/` — build output (gitignored, regenerated by `npm run build`)
- `tests/` — custom validators (see below)
- `.claude/` — Claude Code hooks and settings for this project

## Commands

| Command | Purpose |
|---|---|
| `npm run build` | Production Eleventy build + Tailwind CSS |
| `npm start` | Local dev server on :8080 with live reload |
| `npm test` | **Full validation pipeline** (see below) |
| `npm run test:posts` | Validate post frontmatter schema |
| `npm run test:markdown` | Lint markdown content |
| `npm run test:markdown:fix` | Auto-fix markdown lint issues |
| `npm run test:html` | Validate built HTML in `_site/` |
| `npm run test:build` | Validate build output (links, images, expected files) |

The full `npm test` pipeline runs in this order:

1. `test:posts` — frontmatter schema (fast, no build needed)
2. `test:markdown` — markdown lint (fast)
3. `build` — Eleventy production build
4. `test:html` — HTML validation on built output
5. `test:build` — semantic build validation (every post has output, no broken images)

Each step is a hard gate: if any step fails, the pipeline stops and exits non-zero.

## Blog post format

Every file in `src/posts/` must have frontmatter with at least:

```yaml
---
title: <non-empty string>
date: <parseable date, e.g. 2024-01-15 or 2024-01-15T10:00:00.000Z>
---
```

Recommended extras: `author`, `description`, `tags` (list).

Posts are long-form prose and are frequently bilingual (English/Chinese). Markdown
lint rules are intentionally loose for prose content — see `.markdownlint-cli2.jsonc`.

### Image references

Images live in `src/static/img/` and are referenced in posts as `/static/img/FILENAME`.
**Do not** prefix the path with `/src/` — Eleventy copies `src/static/` to `_site/static/`,
so `/src/static/...` is always broken on the live site. The `test:build` validator will
catch this.

Always provide alt text for images: `![alt text](/static/img/foo.png)`.

## The auto-repair loop (IMPORTANT)

This repo has Claude Code hooks configured in `.claude/settings.json` that run
**after every `Edit` or `Write`** on blog content:

- Editing a `.md` file in `src/posts/` or `src/blog/` triggers `test:posts` + `test:markdown`
- Editing a template in `src/_includes/` triggers a build + `test:html` + `test:build`

When these hooks report a failure, you must:

1. **Read the error message carefully.** The hook prints the exact file, line, and
   rule/check that failed to stderr.
2. **Diagnose the root cause** — do not guess. If the error mentions a missing
   frontmatter field, re-read the file. If it mentions a broken image path, check
   whether the file exists on disk under `src/static/img/`.
3. **Apply the narrowest fix** that makes the test pass. Do not reformat the file,
   do not touch unrelated code.
4. **Re-run the failing test locally** to verify green before moving on:
   - `npm run test:posts` for frontmatter problems
   - `npm run test:markdown` for markdown lint problems
   - `npm run test:build` for build-output / image problems
   - `npm test` for the full pipeline
5. **Repeat** if a new error surfaces after the fix. The loop ends only when the
   relevant test returns exit 0.

Before committing, run `npm test` yourself. The PreToolUse commit gate will re-run
it as a safety net, but you should not rely on the gate to tell you the code is
broken.

### Common failures and fixes

| Failure | Likely fix |
|---|---|
| `Missing required frontmatter field: 'title'` | Add `title: ...` to the post frontmatter |
| `Frontmatter field 'date' is not a valid date` | Use ISO format: `2024-01-15T10:00:00.000Z` |
| `Broken image reference ... /src/static/...` | Change path to `/static/...` (drop the `/src/` prefix) |
| `MD009/no-trailing-spaces` | Run `npm run test:markdown:fix` |
| `close-order` in html-validate | A template is emitting unbalanced tags — check `src/_includes/` |
| `Missing build output for post: ...` | The post exists but Eleventy didn't emit HTML — check frontmatter syntax, especially the YAML block delimiters |

## Git & commit workflow

- This project is on branch `claude/harness-engineering-learning-Uo1RK`.
- Commit messages use imperative mood, short subject line, optional body.
- Before pushing, ensure `npm test` is green.
- Do not create pull requests unless the user explicitly asks.

## What not to do

- Do not disable tests to make them pass. If a test is wrong, fix the test intentionally
  and explain why in the commit message.
- Do not edit `_site/` — it is generated output and will be overwritten by the next build.
- Do not bump dependencies as a side effect of unrelated work.
- Do not add new npm dependencies without a clear reason tied to the task at hand.
